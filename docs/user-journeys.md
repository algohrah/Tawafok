# رحلات المستخدمين والإدارة

> نطاق التحقق: قراءة ساكنة لمصادر GitHub عند Commit `f5cf1caf48cfa2240e4f41fb504aeec759f49802`. لم تُشغّل المنصة أو تُختبر حسابات أو مدفوعات حقيقية. «مؤكد من المصدر» لا يعني «مختبر في الموقع المنشور».

## FLOW-01 — اكتشاف وتسجيل
/ → بحث سريع → /search بمعايير → /member/:id أو /u/:username. إجراء طلب من زائر يوجه للتسجيل أو الدخول. /register خمس خطوات ومراجعة → /profile. /login → المسار المطلوب أو الوجهة الافتراضية. راجع public-pages.md بدلاً من تكرار الحقول.

## FLOW-02 — إدارة حساب
/profile → /edit-profile أو /complete-profile → حفظ → /profile. محفوظات → ملف عضو؛ اشتراك → /plans → /checkout/:planId → نجاح/انتظار مراجعة → /profile. توثيق من نافذة رفع هوية → مراجعة الإدارة. تغيير كلمة الحساب محلي؛ استعادة البريد ليست خدمة إرسال حقيقية مثبتة.

## FLOW-03 — طلب توافق مباشر
ملف عضو → إنشاء طلب → /journey/:id؛ /requests يجمع الطلبات ويوفر روابط الاستفسار والعربون. /journey دون id مسجل لكنه لا يملك معرف طلب صالح، ولا يعني صفحة تفاصيل تعمل تلقائياً.

المراحل المرجعية من src/lib/journey.ts، والتطبيق من localStore.runRequestAction:
| المرحلة | إجراء/شرط المصدر | التالية |
|---|---|---|
| sent | المستلم يقبل أو يعتذر | accepted أو declined |
| accepted | استفسار اختياري أو الانتقال للعربون | seriousness |
| seriousness | دفع العربون لكل طرف | coordination بعد سداد الطرفين |
| coordination | كتابة وإرسال التواصل باختيار كل طرف، ثم تأكيد التقدم | sharia_viewing بعد تحقق التأكيدات |
| sharia_viewing | نتيجة مستقلة من الطرفين | engagement عند نجاح الطرفين؛ declined عند عدم التوافق |
| engagement | تأكيد تسليم المهر وسداد المتبقي لكل طرف | completed بعد سداد الطرفين |
| completed | عرض الإتمام | نهائي |
| declined / cancelled | اعتذار أو إلغاء مع سبب | مسارات نهاية، إعادة تنشيط إدارية ممكنة |

قيم المصدر المرجعية: عربون 500 وأتعاب متبقية 2000 لكل طرف؛ باقة استفسار 100/20 رسالة. القيم الفعلية قد تقرأ إعدادات الإدارة؛ العضوية والرسائل والرحلة مستقلة. النصوص تتضمن رسوم غير مستردة ومهلة 15 يوماً؛ راجع التنفيذ والإعدادات قبل الجزم بانطباقها في كل حالة.

كل رسالة واستجابة قد تستهلك من رصيد صاحب باقة الاستفسار؛ مراجعة إدارية ورسائل معتمدة/معلقة وتعديل وحذف حسب المصدر. توجد simulateReply في طبقة محلية، وليست خدمة ذكاء اصطناعي مثبتة أو اتصال بين أجهزة مستقلة.

مشاركة التواصل لا تسحب هاتف الحساب تلقائياً: طرف يكتب المعلومات ويؤكد ثم يرسل. شاشة الطلب تمنع غير الطرف؛ لا يعد ذلك تدقيقاً أمنياً لخادم.

## FLOW-04 — ملف مستورد ووساطة
بحث/ملف مستورد → طلب → مركز الإدارة /admin/journeys?tab=imported. المسؤول يتواصل مع الخطابة عبر واتساب ويعدّل المرحلة والمدفوعات وملاحظات اللقاء، ويرسل توجيهاً للطرف المسجل. للمسجل متابعة عبر /admin-chat و/requests والرحلة. المستورد ليس بالضرورة عضواً نشطاً يمتلك جلسة؛ لا تفترض مساراً مطابقاً للطرفين المسجلين.

## FLOW-05 — دعم وبلاغ
/contact نموذج زائر أو عضو؛ /support يحول إلى /admin-chat؛ عضو يفتح تذكرة ويتابع الرد والحالة. /admin/trust?tab=messages للمتابعة؛ بلاغ ملف أو مشكلة تواصل → /admin/trust?tab=reports. إشعارات → /notifications → الوجهة المتعلقة بالحدث.

## FLOW-06 — عمل الإدارة
/admin نموذج AdminLayout → مراكز اللوحة. الأعضاء → تفاصيل/تعديل/إجراءات/انتحال → معاينة تجربة العضو ثم الرجوع عبر شريط الانتحال. الطلبات المباشرة → مراحل واستفسارات ومدفوعات. المالية → اعتماد/رفض معاملة وربط أثرها؛ لا تفترض أن كل إجراء يمثل دفعاً حقيقياً.

## FLOW-07 — استيراد وإعداد
members?tab=import → إعداد الجهة/الدفعة والقائمة → رفع أو لصق → مطابقة ومعاينة → تحقق → نتيجة وسجل. قيم غير رسمية → settings?tab=cities للمراجعة والترقية أو الدمج. members?tab=khataaba لإدارة جهات الوساطة والحظر والقوائم. استيراد أعضاء المنصة المصدّرين يوجه إلى settings?tab=backup&section=platform-import. وظائف النسخ والاستعادة موثقة فقط ولم تنفذ.

## حالات فشل واختبارات مستقبلية مطلوبة
- طلب غير موجود، غير طرف، أو طرف محذوف/موقوف/محظور؛ التحقق من التصرف الفعلي لكل إجراء.
- نفاد رصيد ورسالة معلقة وازدواج الطلبات وحدود اليوم والعلاقات ومهلة الدفع.
- انتظار الطرف الآخر لكل دفعة أو تأكيد أو نتيجة؛ إلغاء وإعادة تنشيط وتجميد.
- تعذر API الإدارة والعودة للمحلي؛ عدم إثبات وصول البريد أو دفع أو مشاركة بين جهازين.
- تأخر نشر GitHub Pages أو اختلاف الإصدار أو فشل chunk؛ لا يعالج التوثيق هذه الحالات تلقائياً.
