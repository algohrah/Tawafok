## FLOW-01 — اكتشاف وتسجيل
/ → بحث سريع → /search بمعايير → /member/:id أو /u/:username. إجراء طلب من زائر يوجه للتسجيل أو الدخول. /register خمس خطوات ومراجعة → /profile. /login → المسار المطلوب أو الوجهة الافتراضية. راجع public-pages.md بدلاً من تكرار الحقول.

## FLOW-02 — إدارة حساب
/profile → /edit-profile أو /complete-profile → حفظ → /profile. محفوظات → ملف عضو؛ اشتراك → /plans → /checkout/:planId → نجاح/انتظار مراجعة → /profile. توثيق من نافذة رفع هوية → مراجعة الإدارة. تغيير كلمة الحساب محلي؛ استعادة البريد ليست خدمة إرسال حقيقية مثبتة.

## FLOW-03 — طلب توافق مباشر

طلب منظم بلا رسالة → `sent` → قبول/اعتذار من المستلم، أو إلغاء من المرسل قبل الرد. `/requests` وحدها قائمة الطلبات؛ `/journey/:id` التفاصيل. خمس مراحل فقط:

| المرحلة | ما يحدث ومن يقرر | التالي |
|---|---|---|
| sent | الطرف الآخر يقبل أو يرفض؛ لا رسوم قبل القبول | accepted / declined؛ أو cancelled قبل الرد |
| accepted | موافقة مبدئية وترتيب الدفعة الأولى عبر واتساب الإدارة؛ تُسجّل الإدارة المبلغ الفعلي لكل طرف | الإدارة تعتمد coordination يدوياً |
| coordination | الإدارة تنسّق موافقات وتبادل بيانات أولياء الأمور عبر واتساب | engagement باعتماد الإدارة |
| engagement | توثيق الخطبة وتسليم المهر؛ عند تأكيد المهر يستحق المتبقي الفعلي | completed باعتماد الإدارة |
| completed | توثيق نتيجة مستقلة: بانتظار التأكيد/تم الزواج/لم تكتمل/توقفت/تعذّر التأكيد | ليست إثبات زواج أو سداد تلقائياً |

الافتراضي **٢٥٠٠ لكل طرف**، هدف الدفعة الأولى **٥٠٠**. يمكن اعتماد ٣٠٠ فيبقى ٢٢٠٠؛ سداد جزئي مؤكد يعرض انتظار الإدارة، ولا يطالب العضو تلقائياً بدفعة أولى ثانية. قبل تأكيد المهر لا يظهر إجراء سداد المتبقي. تجميد الطلب يعطل إجراء العضو. لا تحويل تلقائي لمرحلة أو إتمام أو مشاركة أرقام بمجرد الدفع؛ الإدارة تعدّل المراحل بكل الاتجاهات بسبب موثّق. العضوية منفصلة وبأسعارها السابقة.

**بداية نظيفة بقرار المستخدم:** لا تُنقل الرحلات القديمة. عند تهيئة المتصفح بعد SQLite تُمسح الرحلات/أحداثها/توجيهاتها وباقات الاستفسار والإشعارات والمعاملات القديمة الخاصة بالرحلة وإعداداتها، دون ملفات الأعضاء أو الحسابات أو معاملات اشتراك العضوية. التنظيف مرة واحدة؛ يحافظ على الرحلات الجديدة ذات الإصدار 3، حتى عند استعادة لقطة مختلطة. ليس مسحاً مركزياً لأجهزة لم تفتح الإصدار الجديد. لا بيانات رحلات تجريبية تُزرع، ولا إعادة تفعيل للمراسلة الملغاة.

## FLOW-04 — ملف مستورد ووساطة

الطلب المستورد يسلك المراحل الخمس نفسها. `/admin/journeys?tab=imported` يعرض وحدة الإدارة المشتركة بمرشح مستورد. تتواصل الإدارة مع جهة الخطّابة/المكتب للحصول على **قرار صاحب البيانات الفعلي**، ثم تسجّل مصدر القرار والقبول أو الرفض. موافقة الجهة وحدها ليست موافقة صاحب البيانات. لا يفترض امتلاك الملف المستورد جلسة حساب نشط. الإدارة تسجل دفعات كل طرف وموافقات التنسيق والخطبة والمهر والنتيجة للجميع. رابط جهة الوساطة يستخدم حقولها الصريحة ولا يستنتج رقمها من هاتف العضو. المسجّل يتابع في طلباتي/رحلته، وليس بقائمة داخل الدعم.

## FLOW-05 — دعم وبلاغ

`/contact` للاتصال العام؛ `/support` يحول إلى `/admin-chat` المخصص لتذاكر الدعم والاستفسارات فقط. لا تُحمّل طلبات أو مراحل فيه، ولا يفتح `partnerId` تذكرة تنسيق تلقائية. رابط «طلباتي» يقود إلى القائمة المستقلة. التذكرة تعرض رسائل الدعم الحقيقية ولا تنشئ رداً إدارياً محاكياً بعد الإرسال. البلاغات `/admin/trust?tab=reports`؛ إدارة الدعم `/admin/trust?tab=messages`.

## FLOW-06 — عمل الإدارة

الإدارة → مركز الرحلات → طلب → توثيق سبب → تنفيذ إجراء محدد للقسم. تسجيل دفعة فعلية أو تصحيحها بسجل غير مطموس، ضبط المرحلة/التجميد/الاستئناف، موافقات المشاركة، الخطبة والمهر والنتيجة، المتابعة والتوجيهات. المالية العامة لا تعتمد رسم رحلة كدفع ذاتي؛ معاملات اشتراك العضوية لم تُغيّر. المشاركة الفعلية والسداد خارج الموقع عبر واتساب، والإدارة توثّق المعتمد محلياً. صلاحيات محلية وليست حماية خادم أو قاعدة مشتركة مثبتة.

## FLOW-07 — استيراد وإعداد
members?tab=import → إعداد الجهة/الدفعة والقائمة → رفع أو لصق → مطابقة ومعاينة → تحقق → نتيجة وسجل. قيم غير رسمية → settings?tab=cities للمراجعة والترقية أو الدمج. members?tab=khataaba لإدارة جهات الوساطة والحظر والقوائم. استيراد أعضاء المنصة المصدّرين يوجه إلى settings?tab=backup&section=platform-import. وظائف النسخ والاستعادة موثقة فقط ولم تنفذ.

## حالات فشل واختبارات مستقبلية مطلوبة
- طلب غير موجود، غير طرف، أو طرف محذوف/موقوف/محظور؛ التحقق من التصرف الفعلي لكل إجراء.
- روابط غرفة قديمة أو بيانات مستعادة لا تُعيد المراسلة؛ شراء رصيد أو اعتماده ممنوع. تبقى اختبارات ازدواج الطلبات وحدود اليوم والعلاقات وتزامن الأجهزة مطلوبة.
- انتظار الطرف الآخر لكل دفعة أو تأكيد أو نتيجة؛ إلغاء وإعادة تنشيط وتجميد.
- تعذر API الإدارة والعودة للمحلي؛ عدم إثبات وصول البريد أو دفع أو مشاركة بين جهازين.
- تأخر نشر GitHub Pages أو اختلاف الإصدار أو فشل chunk؛ لا يعالج التوثيق هذه الحالات تلقائياً.
